# 架构概览

## 设计目标

DeepSeek Sidebar 是官网的浏览器侧栏容器，而不是独立 AI 客户端。它只打开固定官网地址，不重建聊天界面，不直接调用模型 API。

## 模块

| 文件 | 责任 |
| --- | --- |
| `manifest.json` | Manifest V3 声明、权限、快捷键与侧栏入口 |
| `sidepanel.html` / `sidepanel.css` | 无自制可见控件的全尺寸 iframe |
| `sidepanel.js` | 官网桥接握手、队列逐项投递与确认 |
| `background.js` | 原生菜单、侧栏打开、会话队列和受限嵌入规则 |
| `content.js` | 查找官网输入框、保留草稿并追加文字、不触发发送 |
| `shared.js` | URL、长度上限、规则构造和选择读取 |
| `scripts/` | 静态检查、源码审查、图标生成与打包 |
| `tests/` | 单元测试、浏览器模拟测试和可选真实站点诊断 |

## 消息与投递

1. 用户通过右键或快捷键触发动作，后台在用户手势有效时打开侧栏。
2. 文本通过校验后进入按窗口区分的本地会话队列。
3. 侧栏通过受校验的扩展 Port 订阅状态。
4. 内容脚本与父容器通过带随机 token 的消息握手；双方验证 origin、source 和 namespace。
5. 输入框就绪后顺序追加，官网草稿保留成功后返回确认。
6. 后台收到 ACK 后删除对应队列项。

单个文档内对已完成条目 ID 去重。导航、进程终止或确认丢失时，不能保证跨文档的严格 exactly-once；因此失败会暂停并允许人工检查、重试或清空，不盲目自动重复投递。

## 输入框与页面

内容脚本只在嵌入文档中启用桥接，普通官网顶层标签页不参与。写入 textarea 时使用原生 value setter 与 input 事件；富文本使用浏览器插入路径。不会模拟 Enter、点击发送或调用官网发送接口。

官网 DOM 结构可能变化，输入框识别需要维护。是否能登录、收发消息以及官方功能是否提供，最终取决于官网及浏览器环境。

## 安全边界

所有持久网站权限限定为官网。响应头规则的精确范围及 CSP 取舍见 [隐私与权限](PRIVACY.md)。测试中的代理、证书和模拟页面不是扩展运行架构的一部分。
