# 隐私、权限与安全边界

## 数据流

```text
用户主动选择网页文字
        ↓ 右键菜单 / 快捷键
扩展后台 → 本地 storage.session 队列（按窗口区分）
        ↓ 输入框就绪
DeepSeek 官方网页的原输入框
        ↓ 用户检查并手动发送
DeepSeek 官方服务
```

扩展没有自有服务端、用户账户、统计分析、广告或内容代理。运行时网络活动主要来自嵌入的官网及其资源、认证组件，而不是扩展自建的数据接收端。

官网可以观察输入事件或保存草稿，因此“不自动发送”不意味着内容在点击发送前对官网不可见。不要把不愿交给官网的敏感内容加入其输入框。

## 暂存内容与生命周期

`chrome.storage.session` 存储待添加文字、条目 ID、创建时间、所属窗口及错误提示。不保存来源网页 URL、浏览历史、账号密码、Cookie 或 API Key。

- 每个窗口最多 20 段，每段最多 60,000 字符。
- 写入确认后移除队列项。
- 清空队列、关闭对应窗口或重启浏览器后不再保留相应待添加项。
- 清空队列不会撤回已写入官网的草稿或已发送的消息；已发出的写入请求可能仍会完成。
- 浏览器会话存储不是端到端加密保险箱，也不承诺对本机其他高权限软件隔离。

## 权限清单

| 权限 | 用途 | 边界 |
| --- | --- | --- |
| `sidePanel` | 打开 Chrome 原生侧栏 | 内容区只承载官网 |
| `contextMenus` | 选中文字入口、图标原生菜单 | 由用户主动操作 |
| `activeTab` + `scripting` | 读取当前主文档的选中文字 | 临时授权，不常驻监控所有网页 |
| `storage` | 暂存待添加队列及提示 | 使用本地会话存储，不使用 sync |
| `https://chat.deepseek.com/*` | 加载官网、追加输入框文字 | 唯一持久网站权限 |
| `declarativeNetRequestWithHostAccess` | 允许官网响应在扩展内嵌入 | 仅匹配限定请求 |

扩展不申请 `<all_urls>`、`cookies` 或持久的 `tabs` 权限。某些不敏感的 Tabs API 操作（例如打开官网标签页）仍可在未申请 `tabs` 权限时使用。

## iframe 与响应头处理

动态规则要求同时满足：

1. URL 以 `https://chat.deepseek.com/` 开头；
2. 资源类型是 `sub_frame`；
3. 发起者为当前扩展的 ID。

规则移除该响应的 `X-Frame-Options`、`Content-Security-Policy` 和 `Content-Security-Policy-Report-Only`。

Chrome 声明式响应头 API 无法从未知 CSP 字符串中仅删除 `frame-ancestors` 指令，所以此方案会移除该嵌入响应的**整个 CSP 响应头**。这会降低该文档的部分脚本加载、连接等安全防护，是必须知情的兼容性取舍。

普通官网顶层标签页、其他网站及官网 API/脚本请求不匹配该规则。扩展容器自身仍受 Manifest 中的 CSP 约束；内容脚本不修改官网页面的外观。

HTML meta CSP、客户端跳出框架逻辑或第三方登录策略仍可能阻止嵌入。扩展不关闭 Chrome 的全局安全机制，不绕过验证码或访问控制。

## 登录与 Cookie

登录完全由官网完成。Cookie 和网站存储由浏览器管理，扩展不读取凭据或同步令牌。在已测试的 Chrome 环境中，官网标签页与嵌入官网可共享测试用 Cookie 和 localStorage；企业策略、浏览器版本或隐私设置仍可能影响行为。

出现登录问题时先确认官网标签页可以正常使用。不要为了排查而全局关闭安全功能；若设置网站级例外，应先理解其影响。
